# 忠济堂中医养生连锁管理系统 · 流程状态设计（V3.3）

> **版本：V3.3 | 日期：2026年6月**
> **说明：覆盖所有核心业务对象的状态机设计与状态流转规则**

---

## 一、状态设计原则

| 原则 | 描述 |
|------|------|
| 有限状态 | 状态数量有限，可枚举 |
| 互斥完备 | 状态之间互斥，覆盖所有场景 |
| 事件驱动 | 状态变更由事件触发，记录审计 |
| 不可逆保护 | 关键状态（如退款）需二次确认 |
| 补偿机制 | 可逆操作需设计补偿（逆操作或逆向流程） |

## 二、预约状态机

### 2.1 状态定义

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| 1 | 待确认 | 新建预约，等待门店/技师确认 |
| 2 | 已确认 | 已确认预约，技师已接受 |
| 3 | 服务中 | 客户到店，服务正在进行 |
| 4 | 已完成 | 服务完成，订单已结算 |
| 5 | 已取消 | 预约被取消 |
| 6 | 超时未到 | 预约时间超时，客户未到店 |
| 7 | 已修改 | 预约被修改过，原时段释放 |

### 2.2 状态流转图

```
                    ┌─────────────────┐
                    │   创建预约       │
                    │  (status = 1)   │
                    │   待确认        │
                    └────────┬────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
           ▼                 ▼                 ▼
    ┌────────────┐    ┌────────────┐    ┌────────────┐
    │  技师确认   │    │   取消      │    │  超时未到   │
    │ status = 2 │    │ status = 5 │    │ status = 6 │
    │  已确认    │    │  已取消    │    │ 超时未到  │
    └─────┬──────┘    └────────────┘    └────────────┘
          │
          │ 客户到店签到
          ▼
    ┌────────────┐
    │  服务开始  │
    │ status = 3 │
    │  服务中   │
    └─────┬──────┘
          │
          │ 技师完成服务
          ▼
    ┌────────────┐
    │  服务完成  │
    │ status = 4 │
    │  已完成   │
    └────────────┘

    ┌────────────────────────────────────────────┐
    │  修改预约（已确认状态下）                     │
    │  已确认(2) ──modify──→ 已确认(2)             │
    │  状态不变但 version+1，原时段释放             │
    └────────────────────────────────────────────┘
```

### 2.3 流转规则

| 当前状态 | 事件 | 目标状态 | 前置条件 | 后置动作 |
|----------|------|----------|----------|----------|
| 待确认(1) | confirm | 已确认(2) | 技师在线且房间空闲 | 发送确认通知 |
| 待确认(1) | cancel | 已取消(5) | 取消原因必填 | 释放技师排班+发送通知 |
| 待确认(1) | timeout | 超时未到(6) | 超过预约时间30分钟 | 记录超时 |
| 已确认(2) | check_in | 服务中(3) | 客户到店 | 占用房间+技师 |
| 已确认(2) | modify | 已确认(2) | 新时段可用，version+1 | 释放旧时段+锁定新时段+通知技师 |
| 已确认(2) | cancel | 已取消(5) | 取消原因必填 | 释放时段+发送通知 |
| 已确认(2) | timeout | 超时未到(6) | 超过预约时间30分钟 | 记录超时+线索 |
| 服务中(3) | complete | 已完成(4) | 订单已支付 | 积分+升级+回访任务 |
| 任意状态 | - | 已取消(5) | 非"已完成"状态，取消原因必填 | 退款处理(如已付款)+释放时段+发送通知 |

### 2.4 预约锁档状态

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| locked | 锁定中 | 时段已被锁定，等待确认 |
| confirmed | 已确认 | 锁定已转为预约记录 |
| expired | 已过期释放 | 锁定超时自动释放 |

**锁档流转：**
```
空闲(idle) → 锁定中(locked) → 已确认(confirmed)
                            → 已过期释放(expired)
```

**锁档规则：**
- 锁定时长：5分钟，超时自动释放
- 确认后锁转为预约记录
- 同一时段同一门店不可重复锁定

## 十、预约锁档状态机

### 10.1 状态定义

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| idle | 空闲 | 时段可用，未被锁定 |
| locked | 锁定中 | 时段已被锁定，等待用户确认预约 |
| confirmed | 已确认 | 锁定已转为正式预约记录 |
| expired | 已过期释放 | 锁定超时，时段自动释放回空闲 |

### 10.2 状态流转图

```
    ┌─────────────────┐
    │     空闲(idle)   │
    └────────┬────────┘
             │ 用户选择时段，发起锁定
             ▼
    ┌─────────────────┐
    │  锁定中(locked)  │
    └────┬───────┬─────┘
         │       │
    5分钟内确认   5分钟超时
         │       │
         ▼       ▼
┌───────────┐  ┌───────────────┐
│已确认      │  │已过期释放      │
│(confirmed)│  │(expired)      │
└───────────┘  └───────┬───────┘
                       │ 自动回到空闲
                       ▼
               ┌─────────────────┐
               │     空闲(idle)   │
               └─────────────────┘
```

### 10.3 流转规则

| 当前状态 | 事件 | 目标状态 | 前置条件 | 后置动作 |
|----------|------|----------|----------|----------|
| idle | lock | locked | 时段未被他人锁定 | Redis分布式锁+设置5分钟TTL |
| locked | confirm | confirmed | 用户确认预约 | 锁转为预约记录+扣减可用时段 |
| locked | expire | expired | 超过5分钟未确认 | 自动释放时段+Redis锁删除 |
| expired | - | idle | 自动 | 时段恢复可用 |

**关键规则：**
- 锁定时长：5分钟，超时自动释放（Redis TTL机制）
- 同一时段同一门店不可重复锁定（Redis SETNX保证互斥）
- 确认后锁转为预约记录，时段不可再被他人预约
- 锁定期间用户可主动放弃，立即释放

## 十二、预约修改/取消闭环

### 12.1 修改预约流程

```
    ┌─────────────────────────────────────────────────┐
    │                  修改预约流程                      │
    └─────────────────────────────────────────────────┘

    ① 校验新时段可用
         │
         ▼
    ② 锁定新时段（Redis分布式锁，5分钟TTL）
         │
         ▼
    ③ 释放旧时段（删除旧时段锁定，恢复可用）
         │
         ▼
    ④ 更新预约（version+1，写入新时段信息）
         │
         ▼
    ⑤ 通知技师（推送预约变更通知）
         │
         ▼
    ⑥ 确认完成（新时段锁定转确认）
```

**修改规则：**
- 仅"已确认"状态的预约可修改
- 新时段必须可用，否则修改失败
- 修改采用乐观锁（version字段）防止并发冲突
- 旧时段释放和新时段锁定必须在同一事务中
- 修改成功后预约version+1，状态保持"已确认"

### 12.2 取消预约流程

```
    ┌─────────────────────────────────────────────────┐
    │                  取消预约流程                      │
    └─────────────────────────────────────────────────┘

    ① 校验可取消（状态为待确认/已确认，非服务中/已完成）
         │
         ▼
    ② 填写取消原因（必填，下拉+自定义输入）
         │
         ▼
    ③ 释放时段（删除时段锁定，恢复可用）
         │
         ▼
    ④ 通知技师（推送预约取消通知）
         │
         ▼
    ⑤ 更新预约状态（status → 已取消(5)）
         │
         ▼
    ⑥ 发布取消事件（RocketMQ事件，触发退款/回访等后续流程）
```

**取消规则：**
- 取消原因必填（选项：时间冲突/身体不适/临时有事/其他）
- 取消后时段立即释放，可被他人预约
- 已付款预约取消后自动触发退款流程
- 取消事件通过RocketMQ发布，下游消费处理退款、积分回退等
