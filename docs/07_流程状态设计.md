# 忠济堂中医养生连锁管理系统 · 流程状态设计（V3.3）

> **版本：V3.3 | 日期：2026年6月**
> **说明：覆盖所有核心业务对象的状态机设计与状态流转规则**

---

## 一、状态设计原则

| 原则 | 描述 |
|------|------|
| 有限状态 | 状态数量有限，可枚举 |
| 互斥完备 | 状态之间互斥，覆盖所有场景 |
| 事件驱动 | 状态变更由事件触发，记录审计 |
| 不可逆保护 | 关键状态（如退款）需二次确认 |
| 补偿机制 | 可逆操作需设计补偿（逆操作或逆向流程） |

## 二、预约状态机

### 2.1 状态定义

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| 1 | 待确认 | 新建预约，等待门店/技师确认 |
| 2 | 已确认 | 已确认预约，技师已接受 |
| 3 | 服务中 | 客户到店，服务正在进行 |
| 4 | 已完成 | 服务完成，订单已结算 |
| 5 | 已取消 | 预约被取消 |
| 6 | 超时未到 | 预约时间超时，客户未到店 |

### 2.2 状态流转图

```
                    ┌─────────────────┐
                    │   创建预约       │
                    │  (status = 1)   │
                    │   待确认        │
                    └────────┬────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
           ▼                 ▼                 ▼
    ┌────────────┐    ┌────────────┐    ┌────────────┐
    │  技师确认   │    │   取消      │    │  超时未到   │
    │ status = 2 │    │ status = 5 │    │ status = 6 │
    │  已确认    │    │  已取消    │    │ 超时未到  │
    └─────┬──────┘    └────────────┘    └────────────┘
          │
          │ 客户到店签到
          ▼
    ┌────────────┐
    │  服务开始  │
    │ status = 3 │
    │  服务中   │
    └─────┬──────┘
          │
          │ 技师完成服务
          ▼
    ┌────────────┐
    │  服务完成  │
    │ status = 4 │
    │  已完成   │
    └────────────┘
```

### 2.3 流转规则

| 当前状态 | 事件 | 目标状态 | 前置条件 | 后置动作 |
|----------|------|----------|----------|----------|
| 待确认(1) | confirm | 已确认(2) | 技师在线且房间空闲 | 发送确认通知 |
| 待确认(1) | cancel | 已取消(5) | - | 释放技师排班 |
| 待确认(1) | timeout | 超时未到(6) | 超过预约时间30分钟 | 记录超时 |
| 已确认(2) | check_in | 服务中(3) | 客户到店 | 占用房间+技师 |
| 已确认(2) | cancel | 已取消(5) | 取消原因必填 | 释放排班+发通知 |
| 已确认(2) | timeout | 超时未到(6) | 超过预约时间30分钟 | 记录超时+线索 |
| 服务中(3) | complete | 已完成(4) | 订单已支付 | 积分+升级+回访任务 |
| 任意状态 | - | 已取消(5) | 非"已完成"状态 | 退款处理(如已付款) |

```
    ┌─────────────────┐
    │   创建订单       │
    │  (status = 0)   │
    │   待支付        │
    └────────┬────────┘
             │
      ┌──────┴──────┐
      │             │
      ▼             ▼
┌───────────┐  ┌───────────┐
│  支付成功  │  │  超时关闭  │
│status = 1 │  │status = 4 │
│  已支付   │  │  已关闭   │
└─────┬─────┘  └───────────┘
      │
      │ 全额退款
      ▼
┌───────────┐
│  全额退款  │
│status = 3 │
│  已退款   │
└───────────┘
      ▲
      │ 部分退款
┌───────────┐
│ 部分退款   │
│status = 2 │
└───────────┘
```

### 3.3 支付状态机

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| 0 | 待支付 | 等待支付 |
| 1 | 支付中 | 正在调用支付 |
| 2 | 已支付 | 支付成功 |
| 3 | 支付失败 | 支付失败 |
| 4 | 已关闭 | 超时关闭 |

### 3.4 流转规则

| 当前状态 | 事件 | 目标状态 | 前置条件 | 后置动作 |
|----------|------|----------|----------|----------|
| 待支付(0) | pay_success | 已支付(1) | 支付回调成功 | 积分增加+疗程扣次+AI通知 |
| 待支付(0) | timeout | 已关闭(4) | 30分钟超时 | 释放库存 |
| 已支付(1) | refund_part | 部分退款(2) | 部分退款金额≤已付 | 更新余额+退款记录 |
| 已支付(1) | refund_all | 已退款(3) | - | 全额退款+积分回退+疗程恢复 |
| 部分退款(2) | refund_all | 已退款(3) | - | 剩余金额退款 |

### 5.2 线索分类规则（ABC）

| 分类 | 含义 | 来源 | 分配时效 |
|------|------|------|----------|
| A类 | 高意向，已表达明确需求 | 抖音/美团直接购买意向 | 10分钟内分配 |

| C类 | 低意向，潜在客户 | 关注/点赞/评论 | 24小时内分配 |

## 九、订阅/套餐状态

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| trial | 试用 | 试用期 |
| active | 正式 | 正常使用中 |
| expired | 已过期 | 到期未续费 |
| cancelled | 已取消 | 主动取消 |

### 流转规则

```
试用(trial) → 到期 → 正式(active) → 到期 → 已过期(expired)
试用(trial) → 升级 → 正式(active) → 取消 → 已取消(cancelled)
正式(active) → 续费 → 正式(active)
```

## 十一、事件驱动与审计

### 11.1 状态变更事件

所有状态变更统一通过事件总线(RocketMQ)发布：

```json
{
  "event_type": "appointment.status.changed",
  "event_id": "evt_xxx",
  "timestamp": "2026-06-04T14:30:00+08:00",
  "aggregate_id": 80001,
  "aggregate_type": "appointment",
  "tenant_id": 1001,
  "store_id": 101,
  "payload": {
    "previous_status": 2,
    "current_status": 3,
    "trigger_event": "check_in",
    "operator_id": 3001,
    "operator_type": "technician",
    "extra": {
      "room_id": 1,
      "actual_start_time": "2026-06-04T14:00:00+08:00"
    }
  }
}
```

### 11.2 审计字段规范

| 字段 | 说明 |
|------|------|
| created_at | 创建时间 |
| updated_at | 更新时间 |
| created_by | 创建人ID |
| updated_by | 更新人ID |
| is_deleted | 软删除标记 |
| status_history | JSON数组，记录状态变更历史 |
