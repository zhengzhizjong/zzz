## 五、安全测试标准

### 5.1 安全测试项

| 测试项 | 标准 | 测试方法 |
|--------|------|----------|
| 越权访问 | A租户不可访问B租户数据 | 修改请求头tenant_id，验证返回403 |
| SQL注入 | 所有接口无SQL注入漏洞 | 使用sqlmap扫描所有API |
| XSS | 输入内容正确转义 | 输入`<script>alert(1)</script>`，验证不执行 |
| CSRF | 关键操作有Token校验 | 无Token提交POST请求，验证返回401 |
| 敏感数据 | 手机号/身份证脱敏返回 | 查看API返回数据，验证脱敏格式 |
| 密码存储 | BCrypt加密 | 检查数据库密码字段，验证非明文 |
| 接口鉴权 | 未登录不可访问受保护接口 | 无Token请求，验证返回401 |
| 水平越权 | A用户不可操作B用户数据 | 修改URL中的用户ID，验证返回403 |
| 垂直越权 | 普通用户不可访问管理员接口 | 普通用户Token请求管理接口，验证返回403 |
| 文件上传 | 禁止上传可执行文件 | 上传.jsp/.exe文件，验证被拒绝 |
| 限流 | 超频请求被限流 | 短时间大量请求同一接口，验证429返回 |

```java
/**
 * 预约Service单元测试示例
 */
@ExtendWith(MockitoExtension.class)
class AppointmentServiceTest {

    @Mock
    private AppointmentMapper appointmentMapper;

    @Mock
    private AppointmentLockService lockService;

    @Mock
    private EventPublisher eventPublisher;

    @InjectMocks
    private AppointmentServiceImpl appointmentService;

    @Test
    @DisplayName("创建预约 - 正常场景")
    void createAppointment_success() {
        // Given
        Long tenantId = 1001L;
        TenantContext.setTenantId(tenantId);

        AppointmentCreateRequest request = AppointmentCreateRequest.builder()
                .storeId(2001L)
                .technicianId(3001L)
                .serviceItemId(4001L)
                .startTime(LocalDateTime.of(2026, 6, 15, 14, 0))
                .endTime(LocalDateTime.of(2026, 6, 15, 15, 0))
                .build();

        when(lockService.tryLockTimeSlot(anyLong(), anyString(), anyLong()))
                .thenReturn(Optional.of("lock-id-123"));
        when(appointmentMapper.insert(any())).thenReturn(1);

        // When
        AppointmentResponse response = appointmentService.createAppointment(request);

        // Then
        assertNotNull(response);
        verify(lockService).tryLockTimeSlot(eq(2001L), anyString(), anyLong());
        verify(appointmentMapper).insert(any());
        verify(eventPublisher).publish(any(AppointmentCreatedEvent.class));
    }

    @Test
    @DisplayName("创建预约 - 时段已占用")
    void createAppointment_slotOccupied() {
        // Given
        Long tenantId = 1001L;
        TenantContext.setTenantId(tenantId);

        AppointmentCreateRequest request = AppointmentCreateRequest.builder()
                .storeId(2001L)
                .technicianId(3001L)
                .serviceItemId(4001L)
                .startTime(LocalDateTime.of(2026, 6, 15, 14, 0))
                .endTime(LocalDateTime.of(2026, 6, 15, 15, 0))
                .build();

        when(lockService.tryLockTimeSlot(anyLong(), anyString(), anyLong()))
                .thenReturn(Optional.empty());

        // When & Then
        assertThrows(AppointmentException.class,
                () -> appointmentService.createAppointment(request));
    }

    @AfterEach
    void tearDown() {
        TenantContext.clear();
    }
}
```

```typescript
/**

import { describe, it, expect, vi, beforeEach } from 'vitest'
import { listMembers, createMember } from '@/api/user/member'
import * as request from '@/utils/request'

// Mock request模块
vi.mock('@/utils/request', () => ({
  get: vi.fn(),
  post: vi.fn()
}))

describe('会员API', () => {
  beforeEach(() => {
    vi.clearAllMocks()
  })

  it('listMembers - 正常调用', async () => {
    const mockResponse = {
      code: 0,
      data: { list: [], pagination: { total: 0 } }
    }
    vi.mocked(request.get).mockResolvedValue(mockResponse)

    const result = await listMembers({ page: 1, pageSize: 20 })

    expect(request.get).toHaveBeenCalledWith('/api/v1/user/members', {
      page: 1,
      pageSize: 20
    })
    expect(result.code).toBe(0)
  })

    const mockResponse = { code: 201, data: { id: 1, name: '张三' } }

      name: '张三',
      phone: '13800138000'
    })

  })
})
```

## 八、测试流程规范

### 8.1 测试执行流程

```
开发提交代码
    │
    ▼
CI自动执行：单元测试 + 接口测试
    │
    ├── 失败 → 阻止合并，通知开发修复
    │
    ▼ 通过
MR合并
    │
    ▼
测试环境部署
    │
    ▼
QA执行：功能测试 + 边界测试
    │
    ├── 缺陷 → 提Bug → 开发修复 → 回归测试
    │
    ▼ 通过
发版前执行：E2E测试 + 性能测试 + 安全测试
    │
    ├── 不达标 → 阻止发版
    │
    ▼ 通过
允许发版
```

### 8.2 缺陷等级定义

| 等级 | 定义 | 示例 | 修复时限 |
|------|------|------|----------|
| P0-致命 | 系统崩溃/数据丢失/安全漏洞 | 支付金额错误、SQL注入 | 2小时内 |
| P1-严重 | 核心功能不可用 | 预约创建失败、登录失败 | 24小时内 |
| P2-一般 | 非核心功能异常 | 列表排序错误、样式错位 | 3天内 |
| P3-轻微 | 体验优化 | 文案错误、提示不友好 | 下个版本 |

### 8.3 测试报告输出

每次发版必须输出以下测试报告：

1. **功能测试报告**：用例通过率、缺陷统计、遗留问题
2. **性能测试报告**：各接口P99/QPS/错误率
3. **安全测试报告**：漏洞扫描结果、修复确认
4. **覆盖率报告**：SonarQube代码覆盖率截图
