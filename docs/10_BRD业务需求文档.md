# 忠济堂中医养生连锁管理系统 · BRD业务需求文档（V3.4）

> **版本：V3.4 | 日期：2026年6月**
> **定位：业务需求文档，聚焦业务层面，不涉及技术实现**

---

## 一、业务目标

### 1.1 项目定位

忠济堂中医养生连锁数字化运营平台——面向中医养生连锁集团的全栈数字化运营平台，覆盖客户、前台、技师、店长、片区、总部七端，实现"一个系统完成所有事"。

### 1.2 核心KPI

| KPI指标 | 目标值 | 衡量方式 |
|---------|--------|----------|
| 预约到店率 | ≥70% | 实际到店数 ÷ 确认预约数 × 100% |
| 客户复购率 | ≥40% | 90天内二次消费客户数 ÷ 首次消费客户数 × 100% |
| 技师推广转化率 | ≥15% | 推广注册到店数 ÷ 推广点击数 × 100% |

### 1.3 业务目标分解

| 目标维度 | 具体目标 |
|----------|----------|
| 运营效率 | 预约全流程线上化，减少前台电话预约工作量50%以上 |
| 客户体验 | 预约4步完成，新用户无引导即可操作，到店等待时间≤10分钟 |
| 技师赋能 | 技师推广获客，佣金自动结算，推广转化率可量化 |
| 数据驱动 | 预约漏斗/推广漏斗全链路可统计，数据驱动经营决策 |
| 规模化 | 支持万店级连锁运营，SaaS可租可售，多品牌白标支持 |

## 二、使用角色定义

| 角色 | 使用端 | 核心场景 | 关键操作 | 核心价值 |
|------|--------|----------|----------|----------|
| 客户 | 小程序 | 预约/问诊/消费 | 选门店→选技师→选时间→预约→到店→消费 | 便捷预约、AI问诊、健康档案 |
| 技师 | APP | 接单/服务/推广 | 接单→服务→完成→推广获客 | 提升收入、推广获客、技能提升 |
| 前台/店长 | PC后台 | 收银/排班/客户管理/数据看板 | 收银/排班/客户管理/数据看板 | 提升运营效率、数据驱动决策 |
| 管理员 | PC后台 | 门店/技师/项目/时段配置 | 门店/技师/项目/时段配置 | 系统配置、规则管理 |

### 2.1 客户角色详述

- **典型用户画像**：25-55岁，关注健康养生，有肩颈/腰椎/体质调理需求
- **核心诉求**：快速预约、灵活改约、AI问诊、健康档案管理
- **使用频率**：月均2-4次预约，周均1次浏览
- **关键路径**：首页→预约→选门店→选技师→选时间→确认→到店→评价

### 2.2 技师角色详述

- **典型用户画像**：20-45岁，持证上岗，擅长1-3个养生项目
- **核心诉求**：接单效率、服务SOP、推广获客、佣金结算
- **使用频率**：日均8-12次打开APP，日均服务4-6单
- **关键路径**：工作台→接单→服务→完成→推广→查看佣金

### 2.3 前台/店长角色详述

- **典型用户画像**：22-40岁，门店运营管理，负责收银/排班/客户管理
- **核心诉求**：高效收银、客户管理、数据看板、任务管理
- **使用频率**：日均持续使用，高峰时段集中操作
- **关键路径**：咨询聚合→收银→排班→数据看板→任务管理

### 2.4 管理员角色详述

- **典型用户画像**：总部/片区运营管理人员，负责系统配置和规则管理
- **核心诉求**：门店管理、技师管理、项目配置、时段配置
- **使用频率**：按需使用，新店开业/新员工入职时集中操作
- **关键路径**：门店管理→技师管理→项目配置→时段配置→数据统计

## 三、整体业务链路

### 3.1 预约链路

```
客户浏览门店 → 选技师(含不指定) → 选日期 → 选时段 → 确认预约 → 到店签到 → 服务 → 完成 → 评价
```

**详细步骤说明：**

| 步骤 | 操作方 | 动作 | 业务规则 |
|------|--------|------|----------|
| 1. 浏览门店 | 客户 | 查看门店列表/详情 | 展示营业中门店，按距离排序 |
| 2. 选技师 | 客户 | 选择指定技师或"不指定" | "不指定"为默认选项，系统自动派单 |
| 3. 选日期 | 客户 | 选择预约日期 | 仅可选今天及之后7天 |
| 4. 选时段 | 客户 | 选择预约时段 | 已占时段灰色不可选，选定后5分钟锁档 |
| 5. 确认预约 | 客户 | 确认预约信息并提交 | 必填项缺失时按钮置灰，超时自动释放时段 |
| 6. 到店签到 | 前台/技师 | 确认客户到店 | 预约状态变更为"服务中" |
| 7. 服务 | 技师 | 按SOP执行服务 | 服务计时，SOP节点检查 |
| 8. 完成 | 技师/前台 | 确认服务完成 | 订单结算，积分发放 |
| 9. 评价 | 客户 | 对服务进行评价 | 评价后可获积分奖励 |

### 3.2 改约链路

```
我的预约 → 修改 → 选新时段 → 原时段释放 → 新时段锁定 → 确认 → 通知技师
```

**详细步骤说明：**

| 步骤 | 操作方 | 动作 | 业务规则 |
|------|--------|------|----------|
| 1. 进入我的预约 | 客户 | 查看预约列表 | 仅"待服务"状态显示修改按钮 |
| 2. 点击修改 | 客户 | 打开修改弹窗 | 校验修改次数≤2次 |
| 3. 选新时段 | 客户 | 选择新日期+新时段+新技师 | 新时段校验同预约规则 |
| 4. 原时段释放 | 系统 | 自动释放原预约时段 | 释放后其他客户可预约 |
| 5. 新时段锁定 | 系统 | 锁定新时段5分钟 | 同预约锁档规则 |
| 6. 确认修改 | 客户 | 确认修改信息 | 预约version+1，状态保持"待服务" |
| 7. 通知技师 | 系统 | 推送变更通知 | 如指定技师则推送通知 |

### 3.3 取消链路

```
我的预约 → 取消 → 填原因 → 时段释放 → 通知技师
```

**详细步骤说明：**

| 步骤 | 操作方 | 动作 | 业务规则 |
|------|--------|------|----------|
| 1. 进入我的预约 | 客户 | 查看预约列表 | 仅"待服务"状态且距预约时间>2小时显示取消按钮 |
| 2. 点击取消 | 客户 | 打开取消弹窗 | 二次确认防误操作 |
| 3. 填写原因 | 客户 | 选择取消原因 | 必填，选项：计划变更/时间冲突/身体不适/其他 |
| 4. 确认取消 | 客户 | 确认取消操作 | 预约状态变更为"已取消" |
| 5. 时段释放 | 系统 | 自动释放预约时段 | 释放后其他客户可预约 |
| 6. 通知技师 | 系统 | 推送取消通知 | 如指定技师则推送通知 |
| 7. 退款处理 | 系统 | 如已付款则自动退款 | 按支付原路退回 |

### 3.4 技师推广链路

```
生成海报 → 分享 → 客户点击 → 注册 → 首次到店 → 首单 → 佣金结算
```

**详细步骤说明：**

| 步骤 | 操作方 | 动作 | 业务规则 |
|------|--------|------|----------|
| 1. 生成海报 | 技师 | 一键生成含邀请码的推广海报 | 海报含技师专属二维码+邀请码 |
| 2. 分享 | 技师 | 分享到微信/朋友圈/保存相册 | 记录分享事件，归因到技师 |
| 3. 客户点击 | 客户 | 点击推广链接/扫描二维码 | 记录点击事件，30天归因窗口 |
| 4. 注册 | 客户 | 完成账号注册 | 绑定推广关系，归因到技师 |
| 5. 首次到店 | 客户 | 首次到店签到 | 触发首到标识，记录到店事件 |
| 6. 首单 | 客户 | 完成首次消费 | 触发首单佣金（10%） |
| 7. 佣金结算 | 系统 | T+7自动结算佣金 | 单笔上限200元，结算后技师可提现 |

### 3.5 订单核销链路

```
预约到店 → 前台确认 → 服务 → 收银结算 → 积分发放
```

**详细步骤说明：**

| 步骤 | 操作方 | 动作 | 业务规则 |
|------|--------|------|----------|
| 1. 预约到店 | 客户 | 按预约时间到店 | 前台/技师确认到店，预约状态→服务中 |
| 2. 前台确认 | 前台 | 确认客户身份和预约信息 | 核对客户信息，占用房间+技师 |
| 3. 服务 | 技师 | 按SOP执行服务 | 服务计时，SOP节点检查 |
| 4. 收银结算 | 前台 | 收银结算 | 支持多种支付方式，优惠券核销，疗程扣次 |
| 5. 积分发放 | 系统 | 自动发放消费积分 | 积分实时更新延迟≤3s |

## 四、业务约束规则

### 4.1 预约锁时段

| 规则项 | 说明 |
|--------|------|
| 锁定时长 | 选时段后5分钟内完成确认，超时自动释放 |
| 锁定范围 | 同一时段同一门店不可重复锁定 |
| 锁定展示 | 锁定期间其他用户看到该时段为"锁定中"(灰色+🔒) |
| 超时处理 | 超时未确认，自动释放时段，弹窗提示"预约超时，请重新选择时段" |
| 倒计时展示 | Step3底部和Step4顶部同步显示倒计时，<1分钟变红色警示 |

### 4.2 防重复预约

| 规则项 | 说明 |
|--------|------|
| 限制维度 | 同一客户+同一门店+同一天 |
| 限制数量 | 最多3个有效预约（状态≠已取消） |
| 并发保障 | 数据库唯一索引+分布式锁双重保障，100并发同时段零超卖 |
| 拦截提示 | "您已有该时段的预约" / "您今日在该门店的预约已达上限" |

### 4.3 过期不可改取消

| 规则项 | 说明 |
|--------|------|
| 过期定义 | 预约时间已过的预约 |
| 修改限制 | 过期预约不可修改，隐藏修改按钮 |
| 取消限制 | 过期预约不可取消，隐藏取消按钮 |
| 状态标记 | 过期预约自动标记"已过期" |

### 4.4 不指定技师派单规则

| 规则项 | 说明 |
|--------|------|
| 派单条件 | 客户选择"不指定技师"时触发 |
| 派单策略 | 按技师空闲+技能匹配+轮询分配 |
| 优先级 | 空闲技师 > 技能匹配 > 轮询 |
| 空闲判断 | 技师在岗且该时段无其他预约 |
| 技能匹配 | 技师擅长项目包含客户预约项目 |
| 轮询规则 | 同等条件下按技师编号轮询，确保公平分配 |

### 4.5 历史日期禁用

| 规则项 | 说明 |
|--------|------|
| 禁用范围 | 今天之前的所有日期 |
| 视觉表现 | 历史日期灰色不可选，不可点击 |
| 可选范围 | 今天及之后7天内 |

### 4.6 时段约满灰化

| 规则项 | 说明 |
|--------|------|
| 灰化条件 | 时段已被预约或锁定 |
| 视觉表现 | 灰色背景+🔒图标+"已约"文字，不可点击 |
| 整行约满 | 整行时段全部约满时，整行灰色 |
| 实时刷新 | 时段状态实时刷新延迟≤3s |

### 4.7 修改限制

| 规则项 | 说明 |
|--------|------|
| 状态限制 | 仅"待服务"状态可修改 |
| 次数限制 | 最多修改2次 |
| 超限提示 | "预约最多修改2次" |
| 修改内容 | 可修改日期、时段、技师 |
| 原时段释放 | 修改后原时段自动释放 |

### 4.8 取消限制

| 规则项 | 说明 |
|--------|------|
| 状态限制 | 仅"待服务"状态可取消 |
| 时间限制 | 预约时间前2小时可免费取消 |
| 2小时内 | 2小时内取消记入取消次数，隐藏取消按钮 |
| 取消原因 | 必填，选项：计划变更/时间冲突/身体不适/其他 |
| 时段释放 | 取消后时段立即释放 |

## 五、非功能要求

### 5.1 美观

| 维度 | 要求 |
|------|------|
| 设计系统 | 遵循@zjt/ui设计系统 |
| 风格 | 中医养生风格，绿色主调(#07C160) |
| 色彩 | 主色#07C160(品牌绿)、辅助色#FF9D00(提醒)、警示色#FA5151(错误) |
| 圆角 | 小(4px)/中(8px)/大(12px)/卡片(16px) |
| 阴影 | 轻阴影(0 2px 8px rgba(0,0,0,0.08)) / 重阴影(0 4px 16px rgba(0,0,0,0.12)) |
| 字号 | 12px/14px/16px/18px/20px/24px/32px |
| 品牌白标 | 支持多品牌主题包切换(theme-zhongjitang / theme-xxn / theme-default) |

### 5.2 响应速度

| 指标 | 目标值 |
|------|--------|
| 页面加载 | ≤1s |
| API响应P99 | ≤200ms |
| AI推理响应P99 | ≤3s(客服型)，≤5s(视觉型) |
| 数据刷新延迟 | ≤3s(时段状态)，≤30s(业绩数据) |
| 埋点数据上报延迟 | ≤3s |

### 5.3 并发预约

| 指标 | 目标值 |
|------|--------|
| 并发抢同一时段 | 100并发零超卖 |
| 保障机制 | 数据库唯一索引+分布式锁双重保障 |
| 门店规模 | 支持万店级水平扩展 |
| 用户承载 | 百万级DAU |

### 5.4 数据统计

| 维度 | 要求 |
|------|------|
| 预约漏斗 | 浏览门店→选技师→选时间→确认预约→到店→完成，全链路可统计 |
| 推广漏斗 | 分享→点击→注册→首次到店→首单→复购，全链路可统计 |
| 统计维度 | 门店/技师/日期/时段/渠道 |
| 数据延迟 | 漏斗数据延迟≤5min |
| 下钻分析 | 支持按门店/技师/渠道下钻 |

### 5.5 易用性

| 维度 | 要求 |
|------|------|
| 预约流程 | 4步完成（选门店→选技师→选时间→确认） |
| 新用户引导 | 无引导即可操作，界面自解释 |
| 操作反馈 | 每步操作有明确反馈（高亮/Toast/状态变更） |
| 错误提示 | 错误信息具体明确，引导用户正确操作 |
| 一致性 | 同一操作在不同页面表现一致 |

### 5.6 兼容性

| 项目 | 要求 |
|------|------|
| 客户小程序 | 微信小程序（iOS 12+, Android 8.0+） |
| 技师APP | iOS 13+, Android 10+ |
| PC管理后台 | Chrome/Edge/Firefox/Safari最新两个版本 |
| Pad适配 | iPad/Android Pad横竖屏适配 |

| 法规 | 要求 |
|------|------|
| 个人信息保护法 | 用户授权弹窗+隐私协议 |
